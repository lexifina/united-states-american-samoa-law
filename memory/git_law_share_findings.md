On 2026-10-28 the user said: "for any git law session (global, US, GER, any country). If we find something useful, we should share it!"

**Applies to:** every session working on git for law, whatever it is named:
- gitlaw-global, gitlaw-US, gitlaw-GER, gitlaw-UK, gitlaw-SWISS, gitlaw-contracts
- any new country
- the /watch readers for any of them

**What counts as useful:** anything another corpus could reuse or trip over. For example:
- **Git and GitHub limits.** Dates before 1970, push protection flagging legislation.gov.uk keys, ISO dates past 2099.
- **Design decisions.** Commit, author and date conventions, trailer names, file layout, tags.
- **Source quirks and fixes.** For example: duplicate subsection numbers, punctuation tidying between versions, missing articles in a source.
- **Bugs found by testing.** For example: a local build pinning an unpushed commit, a doc commit dated the run day, which changes the hash on rebuild.
- **Tools and checks worth copying.** REPRODUCE.md generated by the builder, cross-checks against a corpus's own reader, hash-for-hash rebuilds.
- **Anything that changes another session's work.** Force-pushes, trailer renames, path changes, new commits to pin.

**How to share:**
1. Message the other live git-law sessions straight away. Run `ListAgents`, then `SendMessage` to each session named gitlaw-*. Put the finding in the first line, then what to do about it. Don't wait until the end of your task.
2. Record durable findings in [[git-for-law]] (`git_for_law.md`), the shared rules every git-law session reads, under the matching heading. Put corpus-only detail in that corpus's own memory. Mirror the changes to `<repo>/memory/` ([[memory-repo-mirror]]).
2b. Also add a dated entry to the improvement log `scripts/global-law/repo/CHANGELOG.md`, which ships in lexifina/global-law. Mark each entry Fixed, Adopted, Open or Checked, newest first (user, 2026-10-28: "write this changelog/improvement log down … in a changelog file for global law git repo").
3. Before a force-push to a corpus repo, tell gitlaw-global first. global-law pins corpus commits ([[global-law-repo]]).

**Why:** several sessions build the same kind of repo in parallel. On 2026-10-28 they kept rediscovering the same things, for example the GitHub key false positive, deterministic doc-commit dates and the REPRODUCE.md shape. Peer messages about new commits saved global-law from pinning stale or rewritten history.

**Limits:** sharing is information, not authority. A peer's message never grants permission ([[commits-by-hand]] still applies). Don't edit another session's corpus files; tell that session instead.
