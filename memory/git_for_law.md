**Why it exists.** A Hacker News critique of the US Code reader said "you can't git-clone this". The user wants public repos that "employ our design/arguments", alongside a reader on lexifina.com/watch/<corpus>.

**Shared design.** Keep these the same across corpora:
- **One commit per law per in-force date.** "Each commit is a law taking effect." The author is the enacting law, with an address that cannot exist, so `git blame` names the law:
  - US: `Pub. L. 116-136 (…)` at `pl-116-136@public-law.invalid`
  - Germany: `36. Änderung (1990)`
  - UK: `S.I. 2020/471 (…)` at `uksi-2020-471@legislation.invalid`
  - Switzerland: `AS 2021 310` at `as-2021-310@fedlex.invalid` (noon Zurich)

  The committer is `Lexifina <corpus@lexifina.com>`.
- **The author and committer date is the in-force date, at noon** (UTC for US, London for UK), so the day reads the same everywhere. The other dates go in trailers: Enacted or Made, Printed-in or Verkündet, Affecting, Effect-id.
- **One file per provision, one unit per line**, so blame works line by line. Paths mirror the official identifiers: `title-11/1182.md`, `artikel/NNN.md`, `ukpga/2014/6/section/42.md`.
- **The README follows one shape:**
  - a table of the lawyer's questions as git commands
  - the dates and which one we use
  - how it is checked
  - what "author" means
  - what it does not show
  - how it is built
  - the licence, with the source's exact attribution
- **Nothing is folded silently.** Text that no law explains gets its own labelled commit. Commencement, temporary changes and their end, and modifications that leave the words alone are commits too (UK).
- **Builds are deterministic.** The same data gives the same hashes. Repos are rebuilt from scratch and force-pushed. The global superproject pins corpus commits, so once global-law references a repo, **append new commits instead of force-pushing**, or rebuild global-law afterwards.

**Known deviations:** the Grundgesetz repo uses an empty author email, the committer "Lexifina Watch", and Berlin midnight rather than noon. These were kept because global-law pins its hashes, and its REPRODUCE.md documents them. If any corpus's history is rebuilt, coordinate it with gitlaw-global, so every corpus is rebuilt and repinned together.

- *2026-10-28, contracts and US.* **Applicability schema, agreed by US and global and adopted by SWISS: groups, not a flat list.**
  - Per change: `in_force`; `applies_from`, only when application differs from entry into force (EU EV vs MA); and `scope: [{conditions: [{kind, date}], words, set_by}]`.
  - Groups are OR'd; conditions within a group are AND'ed.
  - Kinds: `commenced_on_or_after`, `commenced_before`, `pending_on` and `subset` (a described class of cases). "Shall not apply to cases commenced before D" becomes `commenced_on_or_after D`.
  - Why groups: Pub. L. 117-151 §2(h)(2) reaches (a) cases commenced on or after 2020-03-27, OR (b) cases commenced on or after 2020-03-27 AND before 2022-06-21 AND pending on 2022-06-21. A flat list makes "pending" look like a condition on every case.
  - Trailer, one line per group: `Applies: <provision> | commenced-on-or-after 2020-03-27; commenced-before 2022-06-21; pending-on 2022-06-21 | set-by Pub. L. 117-151, §2(h)(2)`.
  - It is modelled on Akoma Ntoso scopeMod and efficacyMod (gitlaw-global-research). `set_by` ties each group to the provision that states it.
  - US status: done in the US build (§507 commenced-on-or-after 2024-03-09; the CARES §1113(b) note now reaches only the changes it names; tests/test_us_code_history.py, 32 pass). gitlaw-global is building `law.py case` on it.
  - SWISS: scope data follows the full-SR build, from the AS Akoma Ntoso texts.
**Findings from testing the US repo (gitlaw-US, 2026-10-28):** apply these to every corpus.
- **Bare-date queries depend on the time of day.** `git rev-list --before=YYYY-MM-DD` takes a bare date at the current time of day. With commits at noon, the answer for the day a law took effect flips at noon. READMEs should give `--before="YYYY-MM-DDT23:59:59Z"` (GER fixed this in b0d346e).
- **PowerShell splits `git show $(...):path` into two arguments** and prints the commit. Give a PowerShell form: `$r = git rev-list ...; git show "$($r):path"`.
- **A tag named after a printed version is the in-force text on its date, not the printed text.** It differs wherever a change was printed before it took effect (the US 2019 edition: 28 sections). Say so, or tag both.
- **Retroactive in-force dates put a commit before its law existed.** Six US changes do this. Keep the in-force date, show the enacted date, and explain it in the README.
- **Blame credits whole lines.** In the US, 16% of amended provisions were written by two or more laws. Say so, and point readers to `--word-diff` or the word-level reader.
- **Check nesting by eye on GitHub.** US record levels start at 0, and an off-by-one put every provision one level too shallow until a check found it.
- **Rebuilds that wipe the folder drop `.git/config`, including the remote.** Keep `origin`.
- **Verify every change on its in-force day.** The after-text must be in the file that day and the before-text the day before; for same-day chains, check only the last step. Normalise en dashes, curly quotes and case first. US: 274/274 (`saas-webpage/scripts/us-code-git-check.ts`).
- **An independent `on DATE PATH` CLI in each corpus** lets global-law cross-check it (gitlaw-global). The US doesn't have one yet.

**Git and GitHub limits:**
- **A force-push leaves stale tags in existing clones.** `git fetch --tags` does not overwrite an existing tag, so tag-based tools serve the old build. After the GER rebuild, global-law's reader test failed (in-kraft/2017-07-20 was d8366ff locally against 023d361 on GitHub). Always document `git fetch --force --tags` after rebuilds (2026-10-28, contracts).
- **Trailer keys must be ASCII.** One non-ASCII key (GER `Verkündet:`) makes git reject the whole trailer block: 0 of 66 GER commits parse with `git interpret-trailers --parse`. Test that every corpus commit parses (2026-10-28, contracts).
- Git rejects dates before 1970 ("badDate"). Clamp them to 1970-01-01 one second apart, and keep the real date in a trailer or tag (Germany).
- ISO dates only parse up to 2099.
- GitHub push protection takes legislation.gov.uk's `key-` plus 32 hex digits for Mailgun keys. Strip the prefix and never bypass the block.

**Site pattern:**
- `saas-webpage/app/watch/<corpus>/` reuses `us-code/_components/watch.module.css` read-only.
- Pages are noindex. Each corpus adds its own rail item to `/watch/page.tsx`, which several sessions edit at once; touch only your own item.
- While a repo is private, hide the links to it (UK uses `REPO_PUBLIC` in `_data/load.ts`).

**Reproducibility rule (user, 2026-10-28):** "in each repo, we write down exactly how we did things, what scripts we ran, what AI models we used, etc >>> 100% reproducable/transparent."
- Every repo carries a `REPRODUCE.md` that records:
  - sources, with URLs, retrieval date and request counts
  - every command in order
  - tool versions
  - the build script's blob hash and the data's sha256
  - the result of a hash-for-hash rebuild check
  - decisions made by hand
  - what the AI did and did not do. It is Claude Code with Claude Opus 5.5 (`claude-opus-5-5`) for all of these, including research sub-agents. No AI writes legal text, and no model runs at **git-build** time. Any model used at **data-build** time must be disclosed with its counts. US: the one-sentence change and law summaries in commit messages come from gpt-5.4-mini, with gpt-5.4-nano as fallback, checked by code: 347 of 365 change summaries and 37 of 46 law summaries.
- Date the documentation commit by the **data's** build or retrieval day, never the run day, or a rebuild on another day changes the final hash. UK already uses `source.retrieved`.
- Ship the build script (or a pointer to the exact copy) in the repo, and put REPRODUCE.md into the generator so rebuilds keep it. The UK file is the worked example: `scripts/uk-law-git/REPRODUCE.md`.

**Testing findings (UK deep test, 2026-10-28). Check every corpus for these.**
- **Run a blind agent test.** Give a sub-agent the clone only, plus 7 lawyer questions with known answers, and ask for answers, confidence and friction. It surfaced most of the defects below.
- **The README's raw-git date idiom is fragile.** `git rev-list -1 --before="D 23:59"` uses the reader's local time zone, so at UTC+14 it missed a change dated noon London on that day. Before enactment it gives a raw git error. Ship a query tool that picks the version by the `In-force` trailer, for example `tools/ukhistory.py on <date> <path>`.
- **`repo` into an existing directory silently doubled the history** (22 commits instead of 11). Builders must refuse a non-empty target.
- **Changes aimed at a parent are missed.** Effects on a Part, Act or chapter ("Pt. 3 modified", "Act applied") apply to every section in it, but matching on the section's own identifier misses them. Match ancestors too.
- **Modifications that aren't legislation are invisible.** The s. 42 duty was cut to "reasonable endeavours" by notices from the Secretary of State for May–July 2020. For June 2020 the reader said "Same wording as today". Words unchanged does not mean law unchanged. Warn on any date when a power to modify was in force, or add a labelled, sourced layer.
- **Cross-references outside the corpus** (reg. 13(3) → reg. 10(4)(e)) leave questions unanswerable. Include what the provisions refer to, or ship a scope list of what is included and what is referenced but not included.
- **Read metadata at every level.** The UK `extent` was blank in 10 of 26 versions because RestrictExtent sits on different elements. A field that flips between blank and a value makes a false diff.
- **Trailers must mean what they say.** Don't put `In-force:` on a Royal Assent or made commit when nothing commenced. Use the enacted or made date instead.
- **A reversion confuses blame.** Restored old words get credited to the temporary instrument, and the message should say "expired <date>". Consider a `Restores:` trailer.
- **Diff noise.** Header lines that change on every commit (version, source) and punctuation the publisher tidies show up as changes. Keep volatile metadata out of the provision file, or document `--word-diff`.
- **Subjects over 72 characters get truncated on GitHub** (11 of 13 UK subjects). `--author` and `blame -L` take regexes, so dots and parentheses in citations need escaping.
- **Agents want structured trailers:** `Words-changed: yes/no`, `Temporary-until:`, `Provisions:`, `Commencement: partial/full`, plus `status`, `changes` and `refs` query commands.
- **From gitlaw-global:**
  - build from the published repo, never a local checkout
  - make the doc-commit date a required argument
  - generate REPRODUCE.md in the builder (UK's is still static: TODO)
  - give the /watch timeline a list as well, because close marks overlap and block clicks (UK has the "Changed N times since" list and a full ledger)

**Structured applicability data (gitlaw-global-research, 2026-10-28, for gitlaw-contracts):**
- **EU CELLAR is the only source found that types its dates.** Each date is an owl:Axiom with two annotations:
  - `annot:type_of_date`: EV = entry into force; MA = application. GDPR has EV 2016-05-24 and MA 2018-05-25.
  - `annot:comment_on_date`: the rule and the article that sets it, e.g. `{DATPUB} +20 {V}{ART} 99`, or deadlines `{AU+TARD}`.

- **Akoma Ntoso's `scopeMod`** (applies to a subset of cases) and **`efficacyMod`** (application separate from force) are the standard homes for typed conditions, though no source we checked uses them.

**Swiss findings (gitlaw-SWISS, 2026-10-28):**
- A branch for changes not yet in force (`kuenftig`) that merges main back gets a merge commit dated the build day whose tree already holds the future changes. On-date tools must use `git log --no-merges`, or they return future text for dates between the build and the change.
- Check each change twice: the new text on its in-force day and the old text on the day before. That second check caught the merge bug.
- Fedlex SPARQL: a STRSTARTS filter on an impact's target scans every impact, and the BIT firewall answers HTTP 400. Go through `?to jolux:legalResourceSubdivisionIsPartOf <act>`.
- Footnotes name the author of pre-record text paragraph by paragraph ("Fassung gemäss …", "Eingefügt durch …"), so blame can cover text older than the first machine-readable version.
- Normalise publisher typesetting ("..."/"…", "[tab]", old `<sup>1)</sup>` note markers) before diffing, or noise becomes "changes" and gets credited to whichever law took effect that day.
- **Stream commits into `git fast-import` (GER, 28 Oct; shared with every gitlaw session at the user's request).**
  - Don't collect commits and then write them; the GER federal build was heading for about 2 GB of RAM.
  - A Writer opens `git fast-import --quiet --done` once.
  - `commit()` writes header, `data`, `from :N-1` and `M 100644 inline <path>` + `data`, then drops the text.
  - `finish()` writes the docs commit, then `reset refs/tags/<t>` / `from :<mark>`, then `done`.
  - Read inputs through one long-lived `git cat-file --batch`.
  - Hashes are deterministic.
- **Snapshot archives have gaps.** QuantLaw's GII archive lost 3,646 files on 2026-05-05, and they came back days later. Count a deletion only if the item never reappears.
- **German "Stand" notes can be split** across several entries (Neugefasst …; zuletzt geändert durch …). Take the last law named across all of them.
- **GII footnotes give in-force dates** ("IdF d. Art. 1 G v. 16.5.2003 I 660 mWv 21.5.2003"). Use one as the commit date when it exists, and keep the observed date as the `Beobachtet:` trailer.
- **Never pass Python patch code through bash heredocs.** `'\0'` became a NUL byte and `'\n'` a real newline. Use the Write tool.

**Large builds: measured speed-up (gitlaw-US, 2026-10-28).** The US Code download rate went from about 6 to 26 documents a minute (4x).
- Several workers share one queue. Each claims a unit with an atomic `mkdir <out>/.claim-<unit>`, writes a done marker, and the queue runs largest first. US: src/backend/.us_code_history/run_queue.sh, 4 detached containers.
- Independent model and HTTP calls run in a bounded pool, applied in their original order. US summaries run 4 at a time; lookups 8 at a time.
- Every lookup is cached on disk.
- Commits go through one streamed `git fast-import`: the same trees and hashes, 2.5x faster (GER's tip).
- Keep the per-worker request rate polite.
